# 常见反模式与修正

## 一、场景写作

### 1. 把场景列表当灵感大纲
表现：写作时自由发挥，转场省略、动作替换、暗线改掉。
修正：执行 `writing-contract.md` 条款一至三。

### 2. 暗线被"更好的点子"替换
案例：列表设计"端汤出神，想起您的咖啡"，写作时改成"汤面倒影＋口型'报'"——视觉上更花哨，但暗线的因果链断了。
修正：先按列表写；改进作为扩展提交，不擅自替换。

### 3. 转场省略
表现：场景之间硬切，跨风格赶场的视觉资源全部丢失。
修正：转场独立成段，每段写造型/影调/声音中的至少两样。

### 4. 扩展不登记
表现：剧本比列表多出大量细节，用户无法分辨哪些是设计、哪些是自由发挥。
修正：编号登记 → 集中裁决 → 采纳回写。

### 5. 时长失控
表现：单场超 10-15 秒，全片逼近上限却没人发现。
修正：每场报告偏差；超过 10% 提交裁决。

## 二、自检

### 1. 整体感觉式自检
表现："节奏没问题""人设成立"——全是结论，没有依据。
修正：逐项表格，列出每场数值再判断。

### 2. 节奏三连误报
案例：场景 7-9 都是"紧+重"，自检却写"无连续 3 场同节奏"。
修正：先把每场的情节/情感值列成表，再数连续段。

### 3. 报告未经核实
表现：凭记忆写自检报告，与文件实际内容不符。
修正：先读原文，再写判定。

## 三、结构/人物

### 1. Want 与 Need 错位
案例：Need 写"被记住"（外部状态），弧光写"承认在乎"（内部状态）——结局无法同时满足。
修正：Need 必须写在角色内部、角色自己能控制。

### 2. 转变机制空缺
表现："某个瞬间他想通了"——不是设计，是占位符。
修正：钉死一个主动的、当众的、收不回的动作。

### 3. 兑换机制缺失
表现："赶完五场才能保住台词"——为什么？没有硬规则，紧张感悬空。
修正：给出可验证的规则（缺一场全废、日落回收）。

### 4. 情感回扣点过多
表现：四个情感点全部在结尾回扣，导致煽情超载。
修正：主回扣只留一个，其余降为余味或一句台词。

## 四、流程

### 1. 一次性写全片
修正：分批写（第一幕／第二幕／高潮／结局），每批自检。

### 2. 修改后不同步存档
修正：执行 `writing-contract.md` 的文件一致性检查清单。

### 3. 自检发现问题仍继续输出
修正：先改再输出。
